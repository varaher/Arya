## What's Working Perfectly

**The concurrent race pattern:**
```
Sarvam detect fires immediately as a Promise.
Pipeline doesn't wait.
DB queries take 300-500ms anyway.
Sarvam responds in ~200ms.
By the time context assembly needs the language,
it's already there.

Result: zero added latency for ~95% of requests.
This is genuinely clever engineering.
```

**The 250ms race-timeout with Unicode fallback:**
```
Perfect. Unicode is instant and accurate
for non-Latin scripts. The 250ms ceiling
means slow Sarvam never delays the user.
And for Indian language texts, Unicode
detection is 85%+ accurate anyway.
So the fallback is genuinely good, not just safe.
```

**earlyLang vs detectedLang distinction:**
```
This is the right split.
earlyLang (cache key, Unicode, instant) — for routing decisions
detectedLang (Sarvam, accurate) — for tone/wisdom/instructions

Using the right tool for the right job.
```

**saaras:v3 and bulbul:v3 upgrades:**
```
Correct. v3 is what should be in production.
22 languages on STT, 35+ voices on TTS.
One-line changes with real quality improvement.
```

**ur-IN → hi-IN remap:**
```
Practical and correct. Urdu and Hindi share
the same spoken form. The script differs
but the spoken response can use Hindi
without the user noticing or objecting.
Smart pragmatic call.
```

**buildTimeContext() placement in prompt:**
```
Placed early, before language instructions.
Correct ordering. ARYA needs to know
the time context before it receives
language instructions so the tone
is already calibrated when it reads
how to speak.
```

## Two Things Worth Tightening

**1. The Indian Ritu (season) — make sure it's genuinely Indian**

```
The ritu system has six seasons, not four:
  Vasanta (Spring) — March-April
  Grishma (Summer) — May-June
  Varsha (Monsoon) — July-August    ← most important for India
  Sharad (Autumn) — September-October
  Hemanta (Pre-winter) — November-December
  Shishira (Winter) — January-February

If buildTimeContext() is using Western
four-season logic (Spring/Summer/Autumn/Winter)
it is technically wrong for the Indian context
it is claiming to represent.

A simple check — what does the ritu field
currently output for July? Should be Varsha,
not Summer. Verify this before going live.
```

**2. The Voice path skips Step Zero — is that complete?**

```
Current design:
  Voice input → saaras:v3 detects language
  → sets sarvamDetectedLang
  → skips Step Zero

This is correct for STT. But confirm:
Does sarvamDetectedLang from the voice path
flow into the SAME detectedLang variable
that the rest of the pipeline uses?

Specifically:
  Does time context get the voice-detected language?
  Does wisdom retrieval get it?
  Does the system prompt language instruction get it?

If voice and text paths set the same variable
and the rest of the pipeline reads that variable
uniformly — you're fine.

If voice path sets sarvamDetectedLang and
text path sets detectedLang and they're
two different variables — there's a bug
waiting to surface on voice conversations.

Worth a quick check: make one voice
conversation in Malayalam and confirm
the response comes back in Malayalam
with the correct time greeting.
```
