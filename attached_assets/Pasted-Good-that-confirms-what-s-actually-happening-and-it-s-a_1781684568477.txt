## What's Actually Going On

```
There are TWO different install paths
that can both be triggered on a phone:

Path A — Browser's native PWA install prompt
  (the "beforeinstallprompt" event)
  → Installs cleanly as a PWA
  → No Play Protect warning
  → This is what SHOULD be happening

Path B — A custom "Install" button you built
  inside ARYA that's pointing to a downloaded
  .apk file (from one of those PWA→APK

  → THIS triggers Play Protect
  → This is likely what's happening
```

The fact that the warning appears specifically when the user taps your in-app "Install" button — not when they use Chrome's menu — means **your button is linked to an APK file somewhere**, not to the browser's real PWA install flow.

## The Correct Fix — Native PWA Install Prompt

If the button is currently linking to an APK, it needs to be replaced with the proper browser API:

```javascript
// This is the CORRECT way to trigger PWA install
// No APK. No Play Protect warning. No side-loading.

let deferredPrompt;

window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();
  deferredPrompt = e;
  // Now show your custom "Install ARYA" button
  showInstallButton();
});

// When user taps YOUR install button:
installButton.addEventListener('click', async () => {
  if (deferredPrompt) {
    deferredPrompt.prompt();  // ← triggers native install
    const { outcome } = await deferredPrompt.userChoice;
    console.log(outcome); // 'accepted' or 'dismissed'
    deferredPrompt = null;
  }
});
```

This is fundamentally different from downloading an APK — it tells Chrome/Android to install the PWA directly, the same as "Add to Home Screen," but triggered by your own in-app button instead of the browser menu.
